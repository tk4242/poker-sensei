# 成長記録とトークン節約の設計

目的: 同じ間違いを繰り返さないように成長を記録し、そのうえで毎回読み込むトークンを小さく保つ。
作成: 2026-10-05。根拠は Claude Code 公式ドキュメント（取得日 2026-10-05。取得は要約経由のため、細かい数値は原典で再確認できる）。

## 設計
| 層 | ファイル | 読み込み | 中身 |
|---|---|---|---|
| 常時 | `CLAUDE.md`、`.claude/rules/sourcing.md`、`learner/active.md` | 毎回 | ルール、弱点の上位5と1行の再発防止ルール、強み上位3、直近3件（`active.md` は30行以内） |
| 必要時 | `learner/growth.md` | 詳細が要るときだけ | 成長ログ、テーマ別の正答数、傾向メモ（150行以内） |
| 必要時 | `learner/archive/YYYY-MM.md` | 過去を調べるときだけ | 圧縮して移した古いログ |
| 必要時 | `learner/weak-points.md`、`hands/` | 該当のクイズ・レビューのときだけ | 弱点の詳細、ハンド検討 |

- 同じ過ちの防止: 間違いが出るたびに「こういう場面では → こうする」の1行ルールを `active.md` に入れる。再発したら「再発N回」と書いて順位を上げ、3回連続正解で外す。これは常時読み込まれるので、クイズ・レビュー・レッスンのどれでも自動で効く。
- 記録の担当: `growth-tracker`（モデルは `haiku`、`omitClaudeMd: true`）。更新はこのエージェントの独立した文脈の中で行うので、メインの会話に記録の中身が入らない。
- 圧縮: 成長ログが20行を超えたら古い行を `archive/` に移し、1か月を1行に要約する。
- 点検: `python3 tools/context_budget.py` で、常時読み込みファイルの行数・サイズが上限内かを確認する。

## 根拠（公式ドキュメント）
- 常時読み込みは短く: CLAUDE.md は1ファイル200行未満が目安で、長いほど文脈を消費し従われにくくなる。`@path` のインポートは整理には役立つが、インポート先も起動時に読み込まれるので文脈の節約にはならない。→ `active.md` を小さく保ち、詳細は `@` でインポートせず必要時に読む。 https://code.claude.com/docs/en/memory
- 詳細は別ファイルへ: 自動メモリの `MEMORY.md` は先頭200行（または25KB）だけが起動時に読み込まれ、詳しいメモはトピック別ファイルに分ける、という作りになっている。→ 「短い索引を常時、詳細は別ファイル」という本設計と同じ考え方。 https://code.claude.com/docs/en/memory
- 一部のファイルだけに効く指示は、パスを限定したルールに分けると、該当ファイルを扱うときだけ読み込まれる。 https://code.claude.com/docs/en/memory
- サブエージェントは独立した文脈で動き、結果の要約だけを返す。ログのように量の多い作業をサブエージェントに切り出すと、メインの文脈が汚れない。 https://code.claude.com/docs/en/sub-agents
- サブエージェントの `model` フィールドで `haiku` などを指定できる。説明文（`description`）は起動時の文脈を消費するが、本文（プロンプト）は実行時だけ読み込まれる。→ 説明文は短く、詳しい手順は本文に置く。`omitClaudeMd` で CLAUDE.md の読み込みを省略できる。 https://code.claude.com/docs/en/sub-agents
- スキルの `SKILL.md` は500行以内が推奨で、詳しい資料は別ファイルに置くと、参照されたときだけ読み込まれる。 https://code.claude.com/docs/en/skills

## 使い分けの方針（提案）
- 記録・圧縮などの定型作業 → `haiku`（`growth-tracker`）。
- 出題・採点・数学・ハンドレビューなど、正確さが要る作業 → `sonnet` / `opus`（`fact-checker` は `opus`）。
- これは本リポジトリの提案で、公式ドキュメントがモデルの割り当てを指定しているわけではない。記録の質が落ちたら `sonnet` に戻す。
